Submission type

A mod is one folder under mods/, carrying the same fields your manifest.json declares.

A cart is one folder under carts/. It ships no code: it names a base game and pins published mods to exact builds, so every mod on it stays its own entry.

1 · GitHub

Signed out. A submission is a pull request, so it needs your account.

A fine-grained token needs Contents: read&write and Pull requests: read&write on your fork of this index, or use a classic token with public_repo. It is kept in this tab only (sessionStorage), sent straight to api.github.com, and never stored or proxied by this page.

3 · Cart identity

Game speeds optional
The only multipliers the cart permits. Tick one to pin the speed outright, none to allow all.

4 · Pinned mods

A cart is the pin list. Each row names one published build the engine can fetch on its own: a GitHub release by owner/repo, version and zip sha256, or a GameBanana upload by mod, file and md5. Pin builds that are already public -- CI resolves every one of them.

Load order
Rows load top to bottom either way. Tick this only to state the order in the file.
Paste the bundle's pin list instead

5 · Where it downloads from

Set github and the launcher tracks the bundle's Releases the same way it does a mod's, so a version bump does not need a new pull request. The bundle itself is a manifest plus label art: any .lua inside it fails CI.
